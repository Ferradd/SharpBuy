# 🛡️ ПОШАГОВЫЙ ПЛАН ВНЕДРЕНИЯ: СИСТЕМА ГАРАНТИИ И АВТО-ЗАМЕН (SHARPBUY CARE)

Внедрение разбито на **5 независимых, последовательных этапов**, чтобы каждый шаг был тщательно протестирован перед переходом к следующему без риска для основного функционала магазина.

## 📅 ЭТАП 1: Бэкенд интеграция с API замен Shefu (`shefu-replacement.js`)

**Цель:** Создать надёжный модуль для программной проверки и отправки запроса на замену в API Shefu223.

### 📝 Задачи:
1. Исследовать и реализовать метод `checkShefuEligibility(token)`:
   * Отправляет токен `username----token` на эндпоинт `https://nfa.shefu223.shop/api/replacement-check` (или эмуляцию формы).
   * Получает статус: `eligible` (доступно, сколько времени осталось) или `invalid`/`expired`.
2. Реализовать метод `requestShefuReplacement(token)`:
   * Отправляет подтверждение на генерацию замены.
   * Получает новый токен от поставщика в формате `username----token`.
3. Написать изолированный тест `test-replacement.js` для верификации работы с реальным/тестовым токеном.

## 📅 ЭТАП 2: Модуль проверки клиентской гарантии (`api/warranty-check.js`)

**Цель:** Серверный эндпоинт для проверки 3-часовой клиентской гарантии и валидации заказов.

### 📝 Задачи:
1. Создать обработчик `POST /api/warranty-check`:
   * Принимает `{ token: "..." }` от пользователя.
   * Находит соответствующий заказ в `orders_database.json`.
   * Проверяет категорию товара (Prime, Premier, Medals — поддерживают замену; Knife/Rust — отклоняются с пояснением).
   * Вычисляет точный возраст заказа: `(Date.now() - order.paidAt)`.
   * Если прошло `< 3 часов` ➔ вызывает `requestShefuReplacement(token)`.
   * Если прошло `> 3 часов` ➔ возвращает понятный отказ `WARRANTY_EXPIRED`.
2. Обновляет `orders_database.json`, заменяя старый токен на новый, фиксирует `replacedAt: new Date().toISOString()`.
3. Отправляет клиенту новое красивое письмо с замененным токеном через `sendReplacementEmail(...)`.

## 📅 ЭТАП 5: Робот авто-арбитража (Сбор бесплатных аккаунтов на `5h 55m`)

**Цель:** Автоматический сбор бесплатных аккаунтов перед сгоранием 6-часовой гарантии поставщика.

### 📝 Задачи:
1. Создать фоновый воркер / Cron сервис `api/arbitrage-worker.js`:
   * Раз в 5 минут сканирует `orders_database.json`.
   * Находит все проданные аккаунты возрастом от `5ч 50м` до `5ч 58м`.
   * Запрашивает статус у Shefu. Если аккаунт невалиден (хозяин сменил пароль) ➔ забирает бесплатный замененный аккаунт.
2. Сохраняет добытые аккаунты в `src/data/stock_nfa_prime.json` и `steam.txt` как бесплатный готовый склад.
3. Ведет учет прибыли и статистики в `src/data/warranty_stats.json`.
